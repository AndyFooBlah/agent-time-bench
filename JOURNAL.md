# Project journal

An append-only record of how agent-time-bench was built: **decisions** (and who made them), **friction**,
what we **learned**, what **surprised** us, and **incidents**.

**Format:** every entry starts with a UTC timestamp and a tag: `- 2026-10-16T17:52Z [decision] …`. Tags:
`[step]`, `[decision]`, `[friction]`, `[learning]`, `[surprise]`, `[incident]`, `[idea]`, `[milestone]`.
Entries before 2026-10-16T18:00Z were backfilled from commit times, run artifacts, the audit records and
session history, so their timestamps are approximate (`~`). "Owner" is the project owner; "session" is a
Claude Code session.

**Append-only.** Never edit or delete a past entry. To correct one, append a new entry naming the earlier
one's timestamp. Synced daily to `andy-private-docs/journals/`.

- ~2026-07-26T14:50Z [decision] Owner's brief: a benchmark showing the utility of nl2time in agentic systems — a modest number of domains, each with scenarios that exercise both NL→time (tool-call arguments) and time→NL (rendering tool results back to the user), with a baseline condition that has no time tools. 10 domains × 10 scenarios, English first.
- ~2026-07-26T15:00Z [decision] **EvalBench rejected** after reading its current scope: it is a database/NL2SQL evaluation framework — SQL runners, live-DB execution, query scorers. Using it here would mean replacing the runner, the dataset mapping and the scorers, i.e. everything of value. Chose Google ADK agents driven by a thin custom runner, with graders as plain functions over (tool calls, final text). Rationale recorded in `docs/framework-choice.md`.
- ~2026-07-26T15:05Z [decision] ADK's own eval system was also set aside: its built-in trajectory metric is exact-match on whole tool calls, and one evalset assumes one fixed agent, while our tools, mocks and contexts vary per scenario. Graders stay plain functions so they can be registered as ADK custom metrics later if CI-via-`adk eval` becomes attractive.
- ~2026-07-26T15:10Z [decision] The benchmark is **treatment-neutral**: nl2time is *a* measured treatment, not the premise. The baseline condition is a self-contained measurement of agent time competence, and another library can drop into the same slot. This matters for the credibility of the eventual writeup.
- ~2026-07-26T15:20Z [decision] Grading semantics: only the **time-bearing arguments** are graded, against a set of *admissible* argument tuples (coupled args stay coupled); mocks **actually filter** by the bounds the agent passed, so wrong bounds produce wrong data and a wrong answer, as in production; response checks anchor on verifiable facts (a count, a civil day, a wall time) with explicit rejects for the UTC-day reading.
- ~2026-07-26T15:32Z [milestone] Foundation committed: scenario schema, ADK harness, nl2time bridge, and personal-finance as the exemplar domain (b5ecb9c).
- ~2026-07-26T15:33Z [incident] The nl2time cross-check caught **two wrong goldens of my own** — "last week" anchored on a Sunday under a Monday-start convention. Fixed, and the lesson became a hard rule in `docs/authoring.md`: bare week phrases need a midweek `now`, with both conventions admissible and no data on the disputed edge days.
- ~2026-07-26T15:40Z [decision] Golden-correctness discipline: every scenario carries a hand-written `rationale`, a mechanical verifier checks it (offsets real, admissible readings answer-invariant, traps genuinely trapping), and `verifyPhrase` cross-checks against nl2time — where they disagree, the build fails until adjudicated in writing. Direction matters: goldens are derived by hand and *corroborated* by the library, never generated by it.
- ~2026-07-26T15:47Z [milestone] Full corpus: nine further domains authored in parallel by separate sessions following `docs/authoring.md`, all mechanically verified (6447468).
- ~2026-07-26T15:50Z [surprise] Authoring the corpus — before a single model run — surfaced **eight real nl2time bugs** (filed as nl2time #17–#24). The benchmark started paying for itself during construction.
- ~2026-07-26T15:56Z [milestone] Run 1 on gemini-3.5-flash-lite: NL→time 26.9% → 88.5%, time→NL 52% → 81%. Every one of the nine residual treatment failures was nl2time passing through a documented wrong reading — zero model errors.
- ~2026-07-26T16:30Z [learning] Grader fairness needed its own pass. The first graders under-credited correct answers: "yesterday at 5:10 PM" and "last Saturday" identify a day just as well as an explicit date, and a bulleted list of the right N items is a correct count without a stated total. Added deictic acceptance (anchored to the scenario's pinned `now`), once/twice wordforms, and `itemRegex`. Both conditions were regraded identically; the treatment gained more precisely because `describe_time` speaks deictically.
- ~2026-07-26T16:35Z [decision] Built `atb regrade` so recorded transcripts can be re-scored under new graders at zero model cost. Grader iteration stopped being expensive.
- ~2026-07-26T17:49Z [decision] Prompts became versioned artifacts (`prompts/baseline-vN.md`) applied identically to **both** conditions, so the treatment is never measured against a strawman. The explicit goal was to maximise baseline accuracy first, then measure the incremental lift.
- ~2026-07-26T18:00Z [milestone] Blind audit: three independent sessions re-derived all 78 graded expectations from goldens-stripped scenarios using raw `zoneinfo` arithmetic, with no access to the corpus or the library. 57/78 exact agreement; all 21 flags adjudicated.
- ~2026-07-26T18:06Z [decision] The audit's systemic finding: colloquial windows ("Tuesday night", "this morning", "overnight") are *families* of defensible bounds that tuple enumeration cannot cover. Replaced with `admissibleWindow` — pass iff core ⊆ window ⊆ envelope — and the verifier enforces `rows(core) == rows(envelope)` so the fuzziness can never decide a scenario. Two genuine golden gaps fixed; reading policies (weekend = Sat–Sun, sliding windows end at now, night ≥ 20:00) written down.
- ~2026-07-26T18:11Z [learning] After nl2time 0.3.1 landed, the `verifyPhrase` ratchet automatically flagged **eight now-stale disagreement annotations** for removal. The cross-check keeps the corpus honest in both directions, not just at authoring time.
- ~2026-07-26T18:22Z [milestone] Iteration study complete. Prompt engineering moved the baseline 26.9% → 78.2% on arguments and then plateaued; the treatment climbed with the library and the skill to 94.9% / 89%. Residual baseline failures are arithmetic, not knowledge.
- ~2026-07-26T18:20Z [surprise] The **hybrid-rendering trap**: a model takes `describe_time`'s correct deictic ("Friday") and decorates it with a wrong explicit date read off the raw UTC timestamp — "closes Friday, August 1" for a deadline that is Friday July 31 Pacific. Partial tool trust produces a self-contradiction that neither full trust nor no tool produces. Also seen: **UTC re-filtering**, where the model receives correctly-filtered rows and then drops some by eyeballing their raw timestamps.
- ~2026-07-27T22:00Z [step] Multi-model sweep prepared: gitignored `.env` loading, LiteLLM, resumable sweep script, per-model smoke tests. Model IDs verified against live provider docs rather than memory.
- ~2026-07-27T22:30Z [incident] Three provider-side stalls, each costing a rerun: the owner's direct OpenAI account had no quota (rerouted via OpenRouter); OpenRouter's **per-key** spend limit — distinct from account credit — blocked silently with 100% error rows; and the Anthropic balance ran out mid-run. All discarded rather than graded. Added rate-limit-aware retries and an `max_output_tokens` cap, because hosted routers reserve credit against `max_tokens`.
- ~2026-07-28T06:31Z [learning] Reasoning models emit thought parts that are not the answer; the runner was capturing them as final text. Excluded `thought` parts and regraded.
- ~2026-07-28T20:15Z [milestone] Seven-model sweep complete (4e55280). Headline: Gemma 4 26B-A4B 13.7% → 94.0% on tool-call bounds — a ~4B-active open model reaching the frontier models' *baseline*.
- ~2026-07-28T20:15Z [surprise] The two closed frontier models split on **tool adoption**, not capability: Claude Opus 5 follows the skill and gains (91.7→97.4 args, 88→98 rendering), while GPT-5.6 Sol largely ignores the tools, stays flat on arguments and *declines* on rendering. The lift is available to any model that will follow instructions.
- ~2026-07-29T20:39Z [milestone] Writeup published at andrewbrook.dev/writing/agents-and-time/, with the owner's preface recording that the code is AI-written and lightly reviewed.
- ~2026-09-10T22:08Z [step] Deep-audit hygiene: Apache-2.0 + CC BY 4.0 licences declared, direct `google-adk`/`litellm` dependencies instead of the extras group, the 7-model sweep rows committed with a `results/` convention, working Quickstart and SECURITY.md.

- 2026-10-17T04:52Z [incident] **Backfilled timestamps in this journal are seven hours early and are not UTC.**
  Spot-checked against the commits they cite: entries generated with
  `git log --date=format:'%Y-%m-%dT%H:%MZ'` render each commit in its own local zone (here PDT,
  UTC-7) and then have a literal `Z` appended by the format string, so the `Z` is wrong. Add seven
  hours to any entry that was derived from commit times. Entries written from session chronology
  rather than from that command are unaffected, so this journal may mix both.
- 2026-10-17T04:52Z [learning] Correct incantation for a UTC backfill:
  `TZ=UTC git log --date=format-local:'%Y-%m-%dT%H:%MZ'` — `format-local`, not `format`. Appending a
  literal `Z` to a local-time format produces timestamps that look authoritative and are silently
  wrong, which is worse than an obviously missing timezone. This hit several repos in the
  2026-10-16 journal rollout, independently, because the same command was used in each.
